## Objective

아래 인라인된 i18n 감사 리포트의 **분류 기준 타당성과 누락 관점**을 제3자 시각으로 비평한다.

## 검토 대상 (인라인 — 파일 열지 말 것)

**시스템**: 웹 UI(`arms/html` 164개)의 다국어(ko/en/jp). `arms/js/common.js`의 `bindLocaleText()`가 `querySelectorAll("[data-locale]")`로 찾은 DOM만 텍스트를 치환한다. 키가 팩에 없으면 `console.warn`만 남기고 원문을 유지한다. 언어팩 1차 소스는 REST API, 실패 시 `arms/locales/{locale}.json` 폴백.

**감사 판정 기준**: 두 축을 독립 판정. 축①=라벨에 `data-locale` 속성이 있는가(없으면 구조적 미적용). 축②=태깅된 키가 각 언어팩에 값을 갖는가(없으면 키 누락). "적용 완료"는 ①∧②.

**라벨 범위**: 텍스트 노드·placeholder·title·alt·버튼 value·option 포함. script/style/주석/숫자단독 제외.

**주요 결과**:
- 라벨 9,643건 중 태깅 110건(1.14%), 태깅된 파일은 공유 내비 템플릿 6개뿐. 개별 업무 화면 본문은 0건.
- 사용 키 54개 중 ko 22 / en 20 해소, jp 0. 26키(48%)는 어느 팩에도 미정의.
- 결함1: `ko.json`에 trailing comma → JSON 파싱 실패 → 한국어 폴백 전량 무효.
- 결함2: 코드는 `"ja"`를 로케일로 쓰는데 파일명은 `jp.json` → 404. 파일을 채워도 폴백 로드 안 됨.
- 결함3: 빈 `<span data-locale=...></span>` 1건 → 키 미해소 시 버튼 라벨 영구 공백.
- 결함4: JS에 하드코딩 한국어 1,833건. `currentLanguagePack` 변수는 대입만 되고 읽는 코드가 없어 JS 문자열은 현 구조로 번역 불가.
- 병행 스킴: `data-lc-i18n`(12건, ko/en/ja/zh), `data-i18n`(187건, ko/en)이 전역 전환과 미연동.
- 우선순위: P0=코드 1~3줄 수정(쉼표·ja/jp·빈 span·CI 검증), P1=54키 이하 채우기, P3=랜딩보다 내부 업무화면 우선.

**명시된 한계**: 커버리지는 폴백 파일 기준(API 키 집합은 런타임 값이라 정적 조사 불가). 9,643건은 정규식 상한 추정치.
