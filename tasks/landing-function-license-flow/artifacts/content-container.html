POC 라이선스 · 7단계 흐름

JIRA 연결에서 시작해 주간 보고 리포트까지, 아래 순서대로 진행됩니다.

1

STEP 1 · Connect JIRA

고객사 JIRA와 A-RMS를 연결합니다

Admin 권한 계정으로 JIRA 인스턴스를 등록하면 A-RMS가 프로젝트 목록을 읽어옵니다.

  • JIRA Base URL · Admin 계정 · API Token 등록
  • 연결 검증 후 프로젝트 목록 조회
  • 연결 정보는 고객사 단위로 관리됩니다

Connection

JIRA 고객사 인스턴스
● Connected
A-RMS 요구사항 관리
2

STEP 2 · Set Base Version

Default 프로젝트의 Base Version을 설정합니다

고객사 JIRA 프로젝트를 A-RMS Default 프로젝트의 Base Version으로 지정해 기준선을 만듭니다.

  • A-RMS Default 프로젝트에 기준선(Base Version) 생성
  • 고객사 JIRA 프로젝트를 기준선에 연결
  • 이후 수집 · 분석은 이 기준선을 따릅니다

Mapping

JIRA Project CUSTOMER-A
Base Version ARMS / v1.0
JIRA Project CUSTOMER-B
Base Version ARMS / v1.1
3

STEP 3 · Review Mapping

매핑된 이슈의 타입별 우선순위 · 유형을 확인합니다

설정 즉시 자동 매핑된 이슈를 이슈 타입별로 묶어 우선순위와 유형 분포를 확인합니다.

  • Epic · Story · Bug · Task 타입별 집계
  • 우선순위 High · Mid · Low 분포 확인
  • 매핑 누락 이슈를 즉시 식별

4

STEP 4 · Select Requirement

PM · 팀장이 요구사항 이슈를 선정합니다

이슈 리스트에서 EPIC 또는 요구사항 label 등 요구사항에 준하는 이슈를 선정합니다.

  • EPIC 이슈 또는 label 기준으로 후보 필터링
  • 선정된 이슈가 A-RMS 요구사항이 됩니다
  • 선정은 언제든 추가 · 해제할 수 있습니다

5

STEP 5 · Auto Collect

A-RMS가 선정 이슈를 자동으로 수집합니다

선정된 이슈와 하위 이슈 · 변경 이력을 A-RMS가 주기적으로 수집합니다.

  • 선정 이슈의 하위 이슈까지 추적 수집
  • 상태 · 담당자 · 일정 변경 이력 축적
  • 수집 주기는 라이선스 정책에 따릅니다

STEP 6 · 4-Perspective Analysis

Time · Scope · Resource · Cost 관점으로 분석합니다

수집 데이터를 네 관점으로 분석해 프로젝트 상태를 정량화합니다.

  • 일정(Time) — 계획 대비 지연 여부
  • 진척도(Scope) — 요구사항 완료 비율
  • 성과(Resource) — 담당자별 처리 실적
  • ROI(Cost) — 투입 대비 산출
